- **Instead of plans and subscriptions, a manual access profile per customer:** `accounts.CustomerAccess` (1:1 with User, BaseModel), with these fields:
  - `expires_at`: null means no expiry;
  - `max_streams` (default 1) and `max_devices` (default 2);

  `playback.entitlements.build(user)` derives the SPEC §7.4 entitlement object from this profile. The commercial slice later adds subscriptions as another source without changing any consumer. Record this in ADR-0006.
- **Expiry for the POC:** a beat job (every 5 min) refreshes entitlements of customers whose `expires_at` has passed. The entitlement status becomes `expired`, which shows as "Expired" in Xtream. The `subscription_expired` signal becomes `access_expired`, with the same purpose: M7 kicks sessions.
- **Deferred to the final commercial slice (do NOT build now):**

  - §3.5 notifications outbox and Mailpit;
  - trials, payments and invoices;
  - the plans and subscriptions admin pages (§4.2).
- §4.2 admin pages for this slice:
  - login and MFA;

  - customers: list, a create wizard (Profile → Access profile → First device credential), and a success screen with SecretReveal, copy and a QR of `{server, username, password}`;

## 1. Routing and auth topology (ADR-0004, written by builder A)
- Traefik: add routers so `admin.<DOMAIN>` with `PathPrefix(/api)` goes to `web` (priority above the frontend router), and the same for `app.<DOMAIN>` (portal API, used from M11b). Everything else on those hosts stays on `frontend`.
- Django: `ADMIN_HOST` (env, default `admin.<DOMAIN>`) → `config.urls_admin`; `APP_HOST` (default `app.<DOMAIN>`) → `config.urls_portal` (just `api/v1/health` for now). Add both to ALLOWED_HOSTS. `api.<DOMAIN>` keeps `config.urls_api` for external/token clients.
- Admin auth = Django session cookie + CSRF (no JWT for the SPA):
  - SESSION_COOKIE_HTTPONLY, SameSite=Lax; `CSRF_COOKIE_HTTPONLY=False` so the SPA can read `csrftoken`; SPA sends `X-CSRFToken`.
  - `CSRF_TRUSTED_ORIGINS` built from DOMAIN/HTTP_PORT for admin and app origins (http in dev, https in prod).
  - Session lifetime: 30 min idle for staff (SESSION_COOKIE_AGE=1800, SESSION_SAVE_EVERY_REQUEST=True) — SPEC §8.2.
- Why: `admin.localhost` and `api.localhost` are different *sites* to browsers, so cross-host cookie auth would break; same-origin also lets one IP allowlist cover the admin surface (SPEC §11).

## 2. M2 — backend foundation (builder A)
### 2.1 Logging with redaction (SPEC §11, §14)
- structlog: JSON renderer in prod, console renderer in dev; stdlib loggers routed through `structlog.stdlib.ProcessorFormatter`.
- `apps/core/redaction.py`:
  - `redact_text(str) -> str`: Xtream path credentials `/(movie|series|live|timeshift)/<u>/<p>/` → `/<kind>/***/***/`; query/form params `password|pass|username|token|access_token|refresh_token|secret|api_key|key|code` → `=***`; `Bearer <x>` → `Bearer ***`; edge tokens `/v/<token>/` → `/v/***/`.
  - `redact_value(obj)`: recursive; mapping keys matching `password|passwd|secret|token|authorization|cookie|api_key|otp|totp|credential|mfa_code` → `"***"`; strings through `redact_text`.
  - A structlog processor applying `redact_value` to every event dict.
- Request logging middleware (`apps.core.middleware.RequestLogMiddleware`, sync+async capable): request_id from `X-Request-ID` or uuid7; binds request_id/user_id via contextvars; logs method, redacted path, status, latency_ms; sets `X-Request-ID` on the response.
- Remove Gunicorn's `--access-logfile -` and run dev uvicorn with `--no-access-log` (both print raw paths with credentials). The middleware replaces them.
- Tests: redaction unit tests (table-driven), plus `test_no_raw_credentials_in_logs` that drives a request to `/movie/alice/s3cr3t-pass/1.mp4?password=s3cr3t-pass&username=alice` through the middleware and asserts neither secret appears in captured log output.
### 2.2 problem+json errors (SPEC §10)
- `apps/core/errors.py`: `ErrorCode` StrEnum (VALIDATION_ERROR, NOT_AUTHENTICATED, PERMISSION_DENIED, NOT_FOUND, METHOD_NOT_ALLOWED, RATE_LIMITED, INTERNAL_ERROR, INVALID_CREDENTIALS, ACCOUNT_LOCKED, MFA_REQUIRED, MFA_SETUP_REQUIRED, MFA_INVALID, SUBSCRIPTION_EXPIRED, CONCURRENCY_LIMIT, CATEGORY_NOT_ALLOWED, DEVICE_BLOCKED, DEVICE_LIMIT, TITLE_PREPARING, CONFLICT); `ProblemError(APIException)` carrying a code.
- DRF `EXCEPTION_HANDLER` → `{"type", "title", "status", "code", "detail", "field_errors"?}` with `Content-Type: application/problem+json`. `type` = `urn:smart-iptv:problem:<code lowercased with dashes>`. 500s never leak internals.
- Django `handler404`/`handler500` on the admin/api/portal URLconfs return problem+json too.
### 2.3 DRF + OpenAPI (SPEC §8.4, §10)

- REST_FRAMEWORK: SessionAuthentication; IsAuthenticated default; JSON renderer only (browsable API only when DEBUG); PageNumberPagination with `page_size` query param (default 25, max 100); filter backends (DjangoFilterBackend, SearchFilter, OrderingFilter); the problem handler; spectacular AutoSchema.

## 3. M3 — accounts, RBAC, plans, subscriptions (builder C, after A)
### 3.1 accounts
- `User` fields (SPEC §6): email (unique case-insensitively: normalise to lowercase on save + `UniqueConstraint(Lower("email"))`), phone (E.164, validated with `phonenumberslite`), status (`active|suspended|disabled`), locale (`ar|en`), timezone (default `Asia/Riyadh`), notes, mfa_enabled, last_login_ip, marketing_opt_in. `is_staff=True` marks admin users.
- RBAC: `Permission(code, description)`, `Role(name, description, permissions M2M)`, `User.roles` M2M. Data migration seeds permissions (customers.view/edit, subscriptions.view/edit, plans.view/edit, devices.manage, sessions.kill, library.review, billing.refund, settings.view/edit, audit.view, roles.manage, admins.manage, dashboard.view) and roles owner/admin/support/content_manager/viewer with sensible grants (owner = all).
- `accounts.permissions.HasPermission("code")` DRF permission; owner role always passes; non-staff never pass admin endpoints.
- `Device` and `XtreamCredential` per SPEC §6. Credential username `<3 letters of name>-<6 base32 lowercase>` (unique, retry on clash); password 16 chars from an unambiguous alphabet; Argon2id via argon2-cffi (`PasswordHasher` with params tuned so verify p95 < 150 ms — measure in a test and record); constant-time verify. `services.create_device_credential(user, *, name, app_hint, actor) -> (credential, plaintext)`, `reset_credential(credential, *, actor) -> plaintext`, `revoke`. Enforce plan `max_devices` (DEVICE_LIMIT).
- `AccessRule` per SPEC §6 (validated IP/CIDR/country values).
- Admin MFA (TOTP now; WebAuthn added in M14 — note in ADR-0006): `MfaTotp(user 1:1, secret_encrypted, confirmed_at, last_used_step)`; secret encrypted at rest with Fernet (`cryptography`), key from `FIELD_ENCRYPTION_KEY` env (added to `.env.example` as `__GENERATE__`; Fernet keys are urlsafe base64 — make `scripts/secrets.sh` generate the right format for that key). pyotp for TOTP; reject code reuse (last_used_step).
- Login flow (admin host, `/api/v1/auth/*`): `GET csrf` (sets cookie), `POST login {login, password}` (login = username or email) → if staff without MFA: `{status:"mfa_setup_required", otpauth_uri}`; with MFA: `{status:"mfa_required"}`; the half-authenticated state lives in the session (not logged in yet). `POST mfa/verify {code}` → completes login, returns `me`. `POST logout`, `GET me` (user, roles, permission codes, locale). Non-staff users can't log in to the admin host. django-axes (MIT) for lockouts with exponential cool-off; never permanent. Errors use problem codes (INVALID_CREDENTIALS identical for unknown user and wrong password, ACCOUNT_LOCKED, MFA_INVALID).
### 3.2 catalog (minimal now; M6 extends)
- `catalog.Category` (SPEC §6): kind (`vod|series|live`), name_en, name_ar, slug, sort, is_adult, visible_in_xtream, icon, parent (null). Needed by plans.
### 3.3 billing
- `Plan` per SPEC §6 (price in integer minor units + currency; `categories` M2M to Category = PlanCategory; `version` int bumped on change).
- `Subscription` per SPEC §6 with `plan_snapshot` JSON, status, starts_at, ends_at, grace_days, source, auto_renew, created_by; reminder bookkeeping (`reminded_7d_at`, `reminded_1d_at`). ExclusionConstraint (btree_gist): no two `active|grace` subscriptions of the same user overlap in `tstzrange(starts_at, ends_at)`.
- `billing.services.activate(user, plan, *, source, actor=None, payment=None, starts_at=None) -> Subscription`: transaction + row locks; extend the current active/grace subscription (`ends_at = max(now, current_ends_at) + duration`) or create one; snapshot plan; rebuild entitlement; audit; enqueue `account_activated` notification. Also `extend(subscription, days, *, actor)`, `change_plan(...)`, `suspend_user/reactivate_user`.
- Beat every 5 min: `billing.tasks.advance_subscription_states` (active → grace at ends_at, grace → expired after grace_days; on expiry: send `subscription_expired` Django signal (M7 subscribes to kick sessions), rebuild entitlement, enqueue `expired` notification); reminders at T-7d and T-1d deduplicated; updates `iptv_subscriptions{status}` gauge.
- Property-based tests (hypothesis) for renewal date maths and for the state machine.
### 3.4 entitlements (playback app)
- `playback.entitlements.build(user) -> dict` = SPEC §7.4 entitlement object; `refresh(user)` writes `ent:{user_id}` to redis-state with TTL = min(ends_at - now, 1 h); delete when none. Called by billing/accounts services on every relevant change (subscription, plan, rules, user status).
### 3.5 notifications (minimal)
- `notifications.NotificationOutbox` per SPEC §6 + `enqueue(user, template_key, payload, channels=("email",))`; delivery task for the email channel via Django's email backend (Mailpit added to the dev overlay: `axllent/mailpit`, web UI at `mail.<DOMAIN>`). Telegram/WhatsApp come later.
### 3.6 Seed (`make seed`)
- `python manage.py seed_demo`: idempotent. Creates permissions/roles if missing; an owner admin `admin` with a random password printed once (and a note that MFA enrolment happens at first login); plans Basic (1 stream, 2 devices, 720p, 30 days, 2900 SAR minor units = 29.00 SAR), Standard (2/3/1080p, 30 d, 4900), Premium (4/5/2160p, 30 d, 7900), Trial (1/1/720p, 1 day, 0, is_trial); categories (VOD: Action, Comedy, Drama, Science Fiction, Kids, Documentaries — ar/en names; Series: Drama Series, Kids Series; Live: News, Sports); ~24 demo customers with realistic ar/en names, phones (+966…), subscriptions spread across active/grace/expired/trial/suspended and expiry dates (some within 7 days), and 1–2 devices with credentials each. Also `--reset-admin-password`.
### 3.7 Admin API (all under `/api/v1/admin/`, RBAC-guarded, OpenAPI-annotated, paginated)
- `dashboard/kpis`: active subscriptions (+Δ vs 30 days ago), customers total, expiring in 7 days, trials active, grace count, new subscriptions per day for 30 days.
- `customers`: list (search name/email/phone/username; filters status, plan, expiring_within_days, has_trial; ordering), create (wizard payload: profile + plan + start date + optional end-date override + first device credential + optional access rules + notify toggles → response includes the credential password **once**), retrieve (with current subscription, devices), update, `suspend`, `reactivate`, `extend` {days}, `change-plan`, `subscriptions` (history), `devices` (list/create), devices/{id} `block`/`approve`/`revoke`/`reset-credentials` (password once), `access-rules`.
- `plans`: CRUD + `reorder`; `subscriptions`: list with filters; `categories`: list (for the plan editor); `roles`: CRUD; `admins`: list/create (generated password once)/update roles; `audit`; `settings`.
- Each mutation audits. Then `make api-client` regenerates the client.
